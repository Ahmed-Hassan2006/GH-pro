What is GitHub anyway?

Imagine you are writing a book or programming a project. You save a file today, make edits tomorrow, and maybe delete a paragraph the next day. Later on, you might realize that the paragraph you deleted was actually important, but you cannot get it back because you saved over the original file.

This is exactly why GitHub is so useful. It is a cloud storage service (similar to Google Drive or Dropbox), but it is designed specifically to track changes:

  • It saves every version of your file, creating a log of your edits (known as History or Commits).
  • It allows you to share your work with the public (Open Source).
  • It provides a space for people to report problems or suggest ideas for your project (Issues).
  • It allows you to package your finished work so people can easily download it (Releases).

In GitHub, your main project folder is called a Repository (or "Repo" for short).

Step 1: Setup (The Keys to the Kingdom)

Before my program can manage your files on GitHub, it needs your permission. You only need to set this up once.

1. The GitHub Token (Required)

This is the master key that tells GitHub you allow this app to manage your account.

  1. Click this link: Generate GitHub Token (You will need to sign in to GitHub).
  2. Note Name: Type "Git Ready Access App" so you remember what it is for.
  3. Expiration: Choose "No expiration" (so you don't have to repeat this later).
  4. Select Scopes: If you used my link above, all the correct boxes (repo, user, delete_repo, etc.) are already checked for you automatically!
  5. Scroll to the bottom and click "Generate token".
  6. Copy it NOW! You will see a long string starting with ghp_. Copy it immediately, because GitHub will never show it to you again.

What the Scopes Mean

Scope Purpose
repo Full control of public and private repositories, files, and contents.
user Read profile information and user data.
delete_repo Allow deleting repositories from within the app.
workflow Manage GitHub Actions / workflows.
admin:repo_hook Manage webhooks and repository admin operations.

2. Entering the Token in the App

Open Git Ready Access. The login window will appear automatically. Paste your GitHub Token in the box and click Login.
You can change your token later by pressing Ctrl + Shift + S to open the Settings window, going to the Access Keys section, and pasting the new one there.

The Interface & Features

I split the program into two main areas to keep things organized: The Dashboard and the Repository Tab.

1. The Dashboard (Your Headquarters)

This is the first screen you see. It shows a list of all your projects.

Releases: Create & Publish Your Own Versions (New)

You already know how to browse releases with Ctrl + R. But in this new version I added something very powerful: you can now create, edit, and publish your own releases directly from the app — no need to open the website at all!

Creating a Brand New Release

  1. Open the Releases window inside any project (Ctrl + R).
  2. Press the "New Release" button.
  3. Write the version tag, for example v1.0.5. You can also pick an existing tag from the list.
  4. Write a title for the release and the release notes (what is new in this version).
  5. If you want the release to be hidden until you are ready, check the "Draft" box. Otherwise it will be published for everyone.

Uploading Files (Assets) Immediately

The best part: as soon as you choose your files, the upload starts immediately in the background. You do not have to wait for anything.

  • Every file shows its own status: Pending, Uploading (with percentage), or Uploaded.
  • There is a progress bar that shows the overall progress of all files together.
  • You can stop/cancel any file while it is uploading, or delete a file that already finished.
  • If a file fails, the app cleans up after itself so you do not get broken or half-uploaded files on your release.
  • Everything runs in the background, so the window stays responsive and you can keep working.

Editing an Existing Release

Select any release and you can edit it easily: change the tag, update the title and notes, add more files, delete old assets, and save. This is perfect when you forgot to attach a file or made a typo in the notes.

Tip: Releases are the professional way to give your users ready-made packages (ZIP, EXE, APK...). With Git Ready Access, creating a release takes less than a minute.

Pull Requests: Working Together (New)

A Pull Request (PR) is how people suggest changes to your project. Someone copies (forks) your project, makes edits, and then sends you a request to add those changes. Think of it like someone editing a document and then asking: "Please accept my changes."

Now you can handle all of that from inside the app:

  • List all Pull Requests: Open the Pull Requests window from the project's menu. You will see every PR sent to your project.
  • Know their state: Each PR clearly shows if it is Open, Merged, or Closed, so you always know what needs your attention.
  • Read the details: View the PR's title, who sent it, and the full description so you understand exactly what the person wants to change.
  • Merge with one press: When you are happy with a PR, press Merge. The app will ask you to confirm first (so you never merge by accident), then it does the job instantly.
  • After a PR is merged or closed, the button changes to "Merged or Closed" so you can see it is done.

Authentication & Accounts

Two Sign-in Methods

  • Sign in via Browser (OAuth): The app opens the GitHub authorization page in your browser. After you approve, your login is completed automatically, a success message appears, and the login window closes.
  • Sign in via Token: The user pastes a token, which is verified live against GitHub before being saved. Includes a show/hide toggle and a direct link to the token generation page.

Account Registry

  • Multiple accounts can be saved, switched with one click, added, and logged out.
  • All actions in the app are performed with the currently active account.
  • Logging out or resetting data requires an app restart to apply cleanly.

Notifications & Background Polling

The app aggregates notifications from two independent sources:

  • GitHub notifications — threads, mentions, PR/issues/release activity.
  • Administrative notifications — server-pushed messages delivered through a cloud database, addressed per username.

Behavior

  • On startup and after login, both sources are fetched in the background.
  • A poll timer re-fetches notifications every 15 minutes; a tray timer re-checks every 10 minutes.
  • Unread items are visually emphasized; the tray icon shows a desktop notification when new items arrive.
  • Marking an item read (or Mark All Read) updates the source; for administrative messages the read state is pushed back to the database.
  • Activating a GitHub notification opens the correct page (issue, pull request, or releases) in the browser.

The Update Mechanism

Check Flow

  • The app checks for updates on startup (if enabled) and on manual refresh (F5).
  • The app checks a version file on the server for the latest available version.
  • The app compares the server's version against its own; if newer, an Update Prompt dialog appears listing the new version and a changelog.

Changelog Localization

  • Changelog data is stored per-language in a companion file.
  • The app resolves the matching language, falling back progressively: exact code → language-name heuristics → English → first available entry.

The Updater Dialog

  • Offers a choice between Portable (ZIP) and Installer (EXE) versions (versions marked as unavailable are hidden).
  • Actions: Download (through the built-in download manager), Copy Link, or Download in Browser.

The Download Manager

A built-in, IDM-style download window handles every download in the app (files, ZIPs, release assets, updates):

  • Live statistics: file size, download speed, elapsed time, estimated remaining time, and a progress bar.
  • Downloads stream to a staging folder inside the app data directory; on completion the file is moved to the user's Downloads folder.
  • Name collisions are resolved automatically (name (1).ext).
  • Cancel aborts cleanly and deletes the partial file.
  • On completion the user chooses: Open File, Open Folder, or Close.

FAQ & Troubleshooting

The app says "Repo Not Found" when I try to open a link.

Ensure the link is correct. It should look like owner/repo-name. Also, make sure your GitHub Token has the repo scope checked so it can access private repositories.

I see a "Binary File Error".

This happens if you press Ctrl+E to edit an image, PDF, or executable (EXE) file inside the app's internal text editor. Text editors cannot read images or programs! Use Ctrl+D to download the file to your computer instead.

Does it update automatically?

Yes! Every time you open the app, it checks a secure file on my server. If a new version is released, it will pop up asking if you want to update, and it will handle the entire installation process for you.

Can I manage Private Repos?

Absolutely, as long as you checked the "repo" permission box when creating your Token in Step 1.

Is the app free to use?

Yes. Git Ready Access is a public, free-to-use application.

Do I need to keep GitHub open in the browser?

No. The app talks to GitHub directly and manages everything from its own interface.

What happens if two instances are opened?

The second instance detects the running one and exits with a message. Stale locks from crashes are cleared automatically.

Is my token safe?

Yes. Your token is encrypted before it is saved and is stored safely only inside your own user folder.
